<task type="auto">
  <name>Task 2: Implement Node.js HTTP health listener and WebSocket room registry</name>
  <files>server/server.js</files>
  <read_first>server/package.json, .planning/phases/01-dedicated-node-js-websocket-signaling-relay-server/01-RESEARCH.md</read_first>
  <action>
Create `server/server.js` using Node's standard `http` and `ws` library:
1. Configure environment variables (`PORT` defaulting to 3001, `HOST` defaulting to '0.0.0.0').
2. Create `http.createServer` that handles:
   - `GET /health` or `GET /`: returns status 200 with JSON `{ status: 'ok', uptime: process.uptime(), activeRooms: rooms.size }`.
   - Other routes return 404.
3. Attach `WebSocketServer({ server })`.
4. Maintain in-memory `rooms = new Map()` where each room stores:
   - `roomCode`: string
   - `hostSocket`: WebSocket | null
   - `hostId`: string
   - `players`: Map&lt;playerId, { socket: WebSocket, name: string, avatarId: string, joinedAt: number }&gt;
   - `createdAt`: number
   - `lastActive`: number
5. Handle connection events and socket message parsing:
   - `ROOM_CREATE`: validates room code (6 alphanumeric characters), binds socket as host, returns `{ type: 'ROOM_CREATED', roomCode }`. Rejects if room is active with another connected host.
   - `ROOM_JOIN`: verifies room exists, stores player in room, notifies host `{ type: 'PLAYER_JOINED', player: { id, name, avatarId } }`, and replies to player `{ type: 'ROOM_JOINED', roomCode, hostConnected: true }`.
   - `SOCKET_CLOSE`: clean up player or host references and notify counterparty.
  </action>
  <verify>node server/server.js --test-boot 2>/dev/null || curl -s http://localhost:3001/health</verify>
  <acceptance_criteria>
    - `server/server.js` contains `http.createServer`
    - `server/server.js` contains `/health` route returning JSON with status ok
    - `server/server.js` handles `ROOM_CREATE` and `ROOM_JOIN`
  </acceptance_criteria>
  <done>HTTP health server and WebSocket room lifecycle operational</done>
</task>

<task type="auto">
  <name>Task 3: Implement WebRTC signaling router in server</name>
  <files>server/server.js</files>
  <read_first>server/server.js, src/network/peerManager.js</read_first>
  <action>
In `server/server.js`, implement handling for action `SIGNAL`:
- Message shape: `{ action: 'SIGNAL', roomCode, senderId, targetId, signalData }`
- If `targetId === 'host'`: forward message to room's `hostSocket` as `{ type: 'SIGNAL', senderId, signalData }`.
- If `targetId` is a playerId: lookup target player in `room.players` and forward to their socket as `{ type: 'SIGNAL', senderId, signalData }`.
- If target socket is closed or not found, return `{ type: 'SIGNAL_ERROR', error: 'Target peer not connected' }` to sender.
  </action>
  <verify>grep -n "action === 'SIGNAL'" server/server.js</verify>
  <acceptance_criteria>
    - `server/server.js` handles `action === 'SIGNAL'`
    - Forwards SDP offer/answer and ICE candidate payloads to target host or player socket
  </acceptance_criteria>
  <done>WebRTC signaling routing implemented between host and mobile guests</done>
