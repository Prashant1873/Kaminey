# Codebase Concerns

**Analysis Date:** 2026-10-08

## Tech Debt

**Monolithic Orchestrator State Trees:**
- Issue: `HostBaseStation.jsx` (670 lines) and `PlayerController.jsx` (627 lines) handle multiple responsibilities simultaneously: local UI state, game rules state machine, timer intervals, WebRTC message deserialization, and DOM rendering.
- Files: `src/components/host/HostBaseStation.jsx`, `src/components/player/PlayerController.jsx`
- Impact: Modifying phase transitions or adding new game modes requires editing massive switch statements with risk of regression.
- Fix approach: Extract a custom hook or finite state machine reducer (e.g. `useGameStateMachine`, `useNetworkBridge`) to decouple game logic from layout components.

**Thematic Style Inconsistencies:**
- Issue: Several components still use hardcoded hex and rgba color strings (`#ffffff`, `#2a0404`, `rgba(239, 68, 68, 0.08)`) instead of the unified semantic tokens defined in `DESIGN.md` and `src/index.css`.
- Files: `src/components/host/HostDares.jsx:34-47`, `src/components/host/HostNight.jsx:45-60`
- Impact: Light/dark mode switching does not cleanly update these hardcoded sections, resulting in contrast inconsistencies noted in design critiques (`.impeccable/critiques/index-html.md:16`).
- Fix approach: Replace all hardcoded inline color values with theme custom properties (`var(--surface-container)`, `var(--loss-subtle)`).

## Known Bugs

**Aggressive Mobile OS Background Throttling:**
- Symptoms: When a mobile player locks their phone or switches browser tabs during discussion, the WebRTC RTCDataChannel may silently freeze or drop.
- Files: `src/network/peerManager.js:283-345`, `src/components/player/PlayerController.jsx:50-72`
- Trigger: Device enters deep power-save sleep for longer than the 5-second WebRTC keep-alive timeout.
- Workaround: Player must tap refresh or return to the browser tab to trigger `onDisconnect` reconnect logic.

**Public PeerJS Cloud Signaling Outages:**
- Symptoms: Host fails to initialize room code, displaying "Reconnecting room code (1/3)..." or "Could not reach room".
- Files: `src/network/peerManager.js:9-20`, `src/network/peerManager.js:156-178`
- Trigger: Public PeerJS cloud broker (`0.peerjs.com`) downtime or rate limiting.
- Workaround: Fall back to self-hosted PeerServer or provide user notification of signaling relay status.

## Security Considerations

**Public Room Code Namespace Collisions:**
- Risk: PeerJS room IDs are constructed as `kaminey-v2-{ROOM_CODE}` on a shared public signaling broker. A malicious or accidental third party on the internet could guess active room codes and eavesdrop or inject socket traffic.
- Files: `src/network/peerManager.js:7-32`, `src/network/peerManager.js:103-154`
- Current mitigation: Host verifies expected player payloads (`PLAYER_JOIN`) and rejects unrecognized formats; room codes are regenerated on collision.
- Recommendations: Introduce an ephemeral room passphrase or cryptographic HMAC token generated by the host and embedded in the QR code query parameters.

**Host Privileged Inspection:**
- Risk: The Host Base Station holds the master `roles` dictionary in memory (`src/components/host/HostBaseStation.jsx:46`). If the person hosting also plays, they can open browser DevTools to inspect traitor identities.
- Files: `src/components/host/HostBaseStation.jsx:46`
- Current mitigation: Base station UI intentionally conceals traitor identities during discussion and night phases so TV viewers cannot see them.
- Recommendations: Maintain "Host as dedicated living-room display" as the standard recommended play pattern.

## Performance Bottlenecks

**Canvas 2D Trigonometric Loop in TrippyVisualizer:**
- Problem: The interactive visualizer computes trigonometric ray transformations on every animation frame for high-density screens (`devicePixelRatio: 2`).
- Files: `src/components/common/TrippyVisualizer.jsx:45-120`
- Cause: Canvas 2D context software rasterization across large viewports (e.g. 1920x1080 host monitors).
- Improvement path: Offload heavy rendering to WebGL shaders or restrict resolution scaling to a maximum 1.5x pixel ratio.

## Fragile Areas

**Mid-Phase Reconnection Synchronization:**
- Files: `src/components/host/HostBaseStation.jsx:65-108`, `src/network/peerManager.js:103-124`
- Why fragile: If a player drops and reconnects precisely while the host advances from `NIGHT` to `MORNING`, race conditions can lead to an outdated state projection being delivered before the phase increment completes.
- Safe modification: Always verify `readyPlayers` and `gameState.phase` match before sending `STATE_SYNC`.
- Test coverage: Currently validated only manually via test bots.

## Scaling Limits

**Host WebRTC Star Mesh Capacity:**
- Current capacity: Tested for 4 to 12 living-room players.
- Limit: Approximately 16–20 concurrent WebRTC DataChannels before host browser CPU and upstream upload bandwidth cause latency spikes.
- Scaling path: For party sizes > 16 players, migrate from client-hosted star mesh to a lightweight serverless WebSocket relay or SFU architecture.

## Dependencies at Risk

**Lack of TURN Relay Fallback:**
- Package/Infrastructure: Google STUN (`stun:stun.l.google.com:19302`)
- Risk: STUN only resolves non-symmetric NAT traversal. Mobile carriers or university/corporate Wi-Fi networks using symmetric NAT will fail to establish P2P WebRTC data channels.
- Impact: Players on specific mobile carrier networks cannot connect to host on hotel or corporate Wi-Fi.
- Migration plan: Integrate a free/low-cost TURN provider (e.g. Metered.ca, Xirsys, or Cloudflare Calls) as a secondary ICE fallback.

## Missing Critical Features

**Host Game Controls (Pause & Rollback):**
- Problem: Host cannot pause countdown timers or undo an accidental click during council debate.
- Blocks: Recovery from accidental player inputs or kitchen/drink pauses without resetting the entire room.

**In-Game Role Cheat Sheet on Mobile:**
- Problem: During discussion, players only see voting status rather than quick reference for game rules and role powers.
- Blocks: First-time players must ask host for reminders during debate, risking accidental role slips.

## Test Coverage Gaps

**Game Logic Unit Testing:**
- What's not tested: Core game mechanics (role distribution ratios, voting tie-breakers, victory condition evaluators, avatar assignment randomness).
- Files: `src/components/host/HostBaseStation.jsx`, `src/network/peerManager.js`
- Risk: Regressions in win-loss conditions or traitor ratio math can break game balance unnoticed.
- Priority: High.
