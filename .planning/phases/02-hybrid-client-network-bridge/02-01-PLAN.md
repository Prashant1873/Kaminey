<task type="auto">
  <name>Task 2: Implement HybridNetworkBridge dual-transport engine and fallback race</name>
  <files>src/network/hybridBridge.js</files>
  <read_first>src/network/config.js, server/server.js, .planning/phases/02-hybrid-client-network-bridge/02-RESEARCH.md</read_first>
  <action>
Create `src/network/hybridBridge.js` exporting class `HybridNetworkBridge`:
1. Constructor accepts `{ roomCode, role: 'host' | 'player', id, name, avatarId, onMessage, onPlayerJoin, onPlayerLeave, onStatusChange, onModeChange }`.
2. Maintains:
   - `transportMode`: `'CONNECTING'` | `'P2P_DIRECT'` | `'WS_RELAY'` | `'DISCONNECTED'`
   - `ws`: WebSocket connection to server
   - `peerConnection`: RTCPeerConnection (or per-peer map for host)
   - `dataChannels`: Map of peerId -> RTCDataChannel
   - `dedupCache`: Map tracking processed message IDs within a 10s TTL
3. Lifecycle and 4-second race timer:
   - Connects to WebSocket server and sends `ROOM_CREATE` (if host) or `ROOM_JOIN` (if player).
   - Starts a 4.0s timer via `setTimeout`.
   - If WebRTC DataChannel successfully opens (`readyState === 'open'`) before timeout:
     - Clear timeout.
     - Set `transportMode = 'P2P_DIRECT'`.
     - Fire `onModeChange?.('P2P_DIRECT')`.
   - If 4.0s expires before DataChannel opens (or if RTCPeerConnection errors):
     - Set `transportMode = 'WS_RELAY'`.
     - Fire `onModeChange?.('WS_RELAY')`.
     - Log graceful fallback notice.
4. Export DeduplicationCache helper to prevent duplicate message execution.
  </action>
  <verify>test -f src/network/hybridBridge.js</verify>
  <acceptance_criteria>
    - `src/network/hybridBridge.js` exports `HybridNetworkBridge`
    - Contains 4.0s timeout timer for fallback to `WS_RELAY`
    - Tracks `transportMode` and fires `onModeChange`
  </acceptance_criteria>
  <done>HybridNetworkBridge implemented with automatic 4s P2P-to-relay fallback</done>
